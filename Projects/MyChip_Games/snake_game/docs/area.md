# 면적 리포트 (ETRI 0.5um, 실측)

측정 방법: yosys 0.33 로 `khu_etri05_stdcells.lib` 에 매핑한 뒤,
각 셀의 **LEF `SIZE` 실측값**(row height 36um)으로 배치 면적을 계산.
liberty의 `area` 속성은 트랜지스터 면적이라 다이 계획에는 쓰지 않았습니다.
재현: `cd syn && python3 area.py` / `python3 modarea.py`

28핀 프레임(코어 창 약 1.0 mm²)에 어떤 설정으로도 들어가지 않는 이유입니다.

## 3. 패드 프레임 실측

`pads_ETRI/*.mag` 의 배치 좌표를 직접 계산한 값 (lambda = 0.30um,
magic 내부 단위 = lambda/30 = 0.01um):

| 프레임 | 패드 배치 범위 | 다이 | 코어 창(추정) |
|---|---|---|---|
| `MPW_PAD_28Pin_IO` | 189 ~ 1711 um | 약 1.9 x 1.9 mm | **약 1.0 x 1.0 mm** |
| `MPW_PAD_84Pin_IO` | 194 ~ 3606 um | 약 3.8 x 3.8 mm | **약 2.9 x 2.9 mm** |

패드 셀 자체의 깊이는 250.6 um 입니다.

## 4. 이미 적용한 최적화

| 항목 | 효과 |
|---|---|
| 코어 전체를 동기 리셋으로 전환 | `DFFSR`(72x36um) 304개 → 0개. 셀 3.09 → 2.77 mm² |
| 몸통 배열에 리셋을 두지 않음 | 시프트 경로로만 쓰므로 `DFFPOSX1`(36x36um) 유지 |
| 비교기 1개를 시분할 | 마디마다 비교기를 두는 방식 대비 MAXLEN-1개 절약 |
| `i2c_master.div_cnt`, `ms_div` 폭을 파라미터에서 계산 | 플립플롭 약 20개 |

## 5. 더 줄일 여지 (미적용)

**(a) 몸통 시프트 레지스터의 enable 제거 — 약 0.5 mm²**

현재 `seg[]` 는 `shift_en` 으로 게이팅되어 있고, 이 라이브러리에는 클럭 게이팅
셀이 없으므로 합성기가 비트마다 되먹임 mux(약 2게이트)를 답니다.
48 x 11 = 528 비트 x 약 2게이트가 `snake_body` 의 조합 논리 1500게이트 중
대부분입니다.

레지스터를 **매 클럭 자유 회전**시키고 mod-MAXLEN 위상 카운터로 현재 출력의
마디 번호를 추적하면 enable이 사라집니다. `move` 는 위상이 MAXLEN-1 일 때
(즉 가장 오래된 마디가 출력에 있을 때) 새 머리를 주입하면 되고, 최대 지연은
MAXLEN 클럭(1.9us)이라 200ms 게임 스텝에 비하면 무시할 수 있습니다.

대가는 전력입니다. 528개 플립플롭이 25MHz로 항상 토글하므로 대략 7~8mW가
늘어납니다(5V, 활동률 0.5 가정). MPW 면적이 비싼 상황이면 충분히 유리한
교환이고, 배터리 구동이 아니면 문제되지 않습니다.

**(b) `EN_TEXT = 0`** — 폰트에서 알파벳을 빼면 약 0.13 mm². 점수 숫자는 남습니다.

**(c) `SCL_HZ` 를 올리고 `MAXLEN` 을 줄이기** — 프레임레이트에 여유가 크므로
게임성만 허용하면 MAXLEN이 가장 직접적인 레버입니다 (16개마다 약 0.23 mm²).
