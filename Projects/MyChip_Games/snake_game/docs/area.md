# 면적 리포트 (ETRI 0.5um, 실측)

> **정정 이력**: 첫 판에서 "84핀 프레임을 쓰면 된다"고 적었으나 이는 틀렸습니다.
> 2026년 3차 내 칩 제작 서비스 공고 기준으로 **패키지 칩은 `MPW_PAD_28pin`
> 표준 배치만 가능**하고, 그보다 크게 설계하면 사전 협의 후 **bare die만**
> 제공됩니다. 또 utilization을 60%로 가정했으나 실제 테이프아웃 결과는
> 82.3% 였습니다. 아래는 모두 실측으로 다시 계산한 값입니다.

## 1. 면적 예산 — 어디서 나온 숫자인가

### 1-1. 코어 창: 1018 x 1018 um

DK 안의 실제 테이프아웃 결과물
(`Projects/RTL/pong_pt1/ETRI050_MyChip_MPW/pong_pt1_MPW2025_STD-II.tar.gz`)의
chip_top 레이아웃을 직접 측정했습니다. (lambda = 0.30um, magic 내부 단위 = 0.01um)

| 레이어 | 범위 | 크기 |
|---|---|---|
| `pong_pt1_Pad.mag` (패드링) | 91.5 ~ 1808.5 um | 1717 x 1717 um |
| `pong_pt1_Pin_Route.mag` (핀 라우팅 링) | **441.0 ~ 1459.0 um** | **1018 x 1018 um** |

핀 라우팅 링 안쪽이 코어가 쓸 수 있는 전부입니다.
**1018 x 1018 um = 1.036 mm²**, 공고문의 "GPIO 사용시 설계 면적 ~1.0mm x 1.0mm"와
일치합니다.

### 1-2. Utilization: 82.3%

같은 테이프아웃의 라우팅 완료 DEF (`pong_pt1.def`)에서:

```
DIEAREA (0,-600) (86400,83700)   ->  864.0 x 843.0 um = 0.7284 mm2
COMPONENTS 2065  ->  실제 셀 1017개 + FILL 1048개
실제 셀 면적 합 (LEF SIZE 기준)  =  0.5997 mm2
utilisation = 0.5997 / 0.7284   =  82.3 %
```

qflow(graywolf `initial_density = 0.85` + qrouter, 3-metal)의 실제 달성치입니다.

### 1-3. 따라서 예산

```
코어 창      1.036 mm2
x 82.3%   =  0.853 mm2 의 표준셀
          =  약 1974 GE  (GE = NAND2X1 면적 432 um2 기준)
```

## 3. 최적화 기록

| 항목 | 효과 |
|---|---|
| 코어 전체를 동기 리셋으로 | `DFFSR`(72x36um) 304개 → 0개. 3.09 → 2.77 mm² |
| **몸통을 좌표 큐 → 방향 큐로** | 좌표 11bit x 48 = 528 FF → 방향 2bit x 48 = 96 FF. snake_body 3331 → 1078 GE |
| pixel_gen의 벽/먹이 마스크 공유 | 픽셀 행 8개 비교기 → 상수 마스크 + 비교기 1개 |
| **위치 연산을 snake_body로 이동** | game_ctrl에서 11bit 레지스터 2개와 그 먹스 트리 제거. 998 → 552 GE, FF 92 → 52 |
| oled_ctrl 중복 레지스터 제거 | `pix_x`/`pix_page`/`i2c_din` → 조합 논리. 프레임 윈도우 명령을 init에 통합 |
| debounce 3샘플 → 2샘플, lfsr16 → lfsr11 | FF 21개 |

**누적: 2.769 → 1.423 mm² (동일 기능 기준 -49%).** 기능 손실은 없습니다
(19개 시스템 체크 + CELL_SH 1/2/3 렌더러 단위검증 전부 통과, 점수만 3자리 → 2자리).

방향 큐 전환의 부수 효과로 그리드 해상도와 뱀 길이가 거의 공짜가 되었습니다.
2x2 px/48칸과 8x8 px/16칸의 차이는 0.44 mm² 뿐입니다.

## 4. 왜 더 못 줄이는가

ablation으로 측정한 결과, 개별 게임 기능은 전부 작습니다.

| 제거 대상 | 절감 |
|---|---|
| 점수 BCD 3자리 | 39 GE |
| 속도 테이블 → 고정 200ms | 64 GE |
| 먹이 범위 검사 | 8 GE |
| 벽 판정 | 43 GE |
| init ROM 26바이트 → 상수 | 114 GE |

즉 면적은 게임 규칙이 아니라 **"폭 넓은 레지스터 × 여러 FSM 상태"의 next-state
먹스 트리**에 있습니다. 그래서 효과가 컸던 최적화는 전부 *레지스터를 없앤* 것들
이었습니다(방향 큐, 위치 연산 이동, 중복 레지스터 제거).

남은 블록은 더 이상 줄일 여지가 크지 않습니다.

* `snake_body` 942 GE — FF 106개(318 GE)가 절반. 방향 큐는 이미 최소 표현입니다.
* `oled_ctrl` + `i2c_master` 736 GE — 패널과 대화하는 최소 논리.
* `game_ctrl` 552 GE — FF 52개짜리 FSM.

SPI로 바꾸면 `i2c_master`가 약 100 GE로 줄고 `oled_ctrl`에서 주소 바이트/ACK/
control byte 처리가 빠져 총 약 320 GE(0.14 mm²)를 아낍니다. 그래도 최소 설정이
1.15배 수준이라 예산 안에는 들어오지 않습니다.

## 5. 결론

**현 구조로는 28핀 패키지 칩(코어 1.036 mm²)에 들어가지 않습니다.**
가장 극단적으로 깎은 설정(8x8 px 그리드, 16칸 뱀, 점수·텍스트 없음)이 1.356 mm²,
예산의 1.31배입니다. 남은 선택지는 셋입니다.

1. **Bare die로 제작** (사전 협의, 패키지 없음). 표준 1.9x1.9mm 다이 안에 커스텀
   패드를 배치하면 4x4 px / MAXLEN 24 설정(코어 1.619 mm² → 한 변 1.27mm,
   패드 깊이 250um x 2 = 0.5mm, scribe 0.12mm → 1.89mm)이 들어갑니다.
   단 본딩(COB)을 직접 해야 하므로 동작 확인이 어렵습니다.
2. **다음 차수를 목표로 계속 최적화.** 지금까지 49%를 줄였지만 남은 31%는
   구조적으로 어렵습니다.
3. **칩은 MCU와 함께 쓰는 기존 MyChip_Games 방식으로 되돌리기.** 면적은 충분히
   들어가지만 "칩 하나로 동작"이라는 목표를 포기하게 됩니다.
