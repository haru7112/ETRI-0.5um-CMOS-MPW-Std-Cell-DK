# 결선 가이드

## 1. 실칩 (ETRI 0.5um, 5V)

```
                         VDD 5V
                           │
              ┌────────────┴────────────┐
   10k x5 ────┤ (조이스틱 풀업)         │
              │                         │
   ┌──────────┴──────────┐              │      3V3
   │   5-way switch      │              │       │
   │  UP DN LT RT OK COM │              │      4.7k x2
   └───┬──┬──┬──┬──┬──┬──┘              │       │
       │  │  │  │  │  └── GND           │   ┌───┴────┐
       ▼  ▼  ▼  ▼  ▼                    │   │        │
  ┌────────────────────────────┐        │  SCL      SDA
  │  JS_UP JS_DOWN JS_LEFT     │        │   │        │
  │  JS_RIGHT JS_OK            │        │   └───┬────┘
  │                            │        │       │
  │       snake_chip      SCL ─┼────────┼───────┤
  │                       SDA ─┼────────┼───────┤   ┌──────────────┐
  │                OLED_RES_N ─┼────────────────┼───┤ SSD1315 OLED │
  │                            │                └───┤ VCC 3V3      │
  │  CLK   RST_N          LED ─┼──[330R]──▶|──GND   │ GND          │
  └───┬──────┬─────────────────┘                    └──────────────┘
      │      │
   25MHz    RC (10k / 10uF)
   OSC      → RST_N
```

### 부품

| 부품 | 값 / 품번 예시 | 비고 |
|---|---|---|
| 오실레이터 | 25.000 MHz, CMOS 출력, 5V | 크리스탈이 아니라 **오실레이터 모듈**. 칩 안에 발진 회로가 없습니다 |
| OLED | SSD1315 또는 SSD1306 128x64 I2C, 주소 0x3C | 두 컨트롤러의 명령 집합은 이 설계가 쓰는 범위에서 동일합니다 |
| I2C 풀업 | 4.7k x 2 → **3.3V** | 모듈에 이미 달려 있으면 생략 |
| 조이스틱 | 5방향 네비게이션 스위치 (디지털 접점) | 아날로그 썸스틱(KY-023)은 ADC가 없어 직결 불가 |
| 조이스틱 풀업 | 10k x 5 → 5V | `PADINC` 에는 내장 풀업이 없습니다 |
| 리셋 | 10k + 10uF → RST_N, 다이오드 병렬 | 약 100ms 리셋 |
| 디커플링 | 100nF x N + 10uF | VDD 핀마다 |

### 5V 칩과 3.3V 패널

이 설계는 I2C 라인을 **끌어내리기만** 하고 절대 High로 밀지 않습니다
(`PADINOUT` 의 `DO`를 GND에 고정하고 `OEN`만 제어). 따라서 버스의 High 레벨은
풀업 저항이 연결된 전압으로 결정됩니다.

* 풀업을 **3.3V** 로 올리면 → 패널은 3.3V만 봅니다. 안전합니다.
* 칩 입력(`SDA_I`)이 3.3V High를 5V CMOS 입력으로 읽어야 하는데, ETRI050
  `PADINC` 의 입력 임계는 약 VDD/2 = 2.5V 이므로 3.3V는 확실한 High입니다.
* 풀업을 5V로 올리지 마세요. 대부분의 SSD1315 모듈은 로직 레벨 시프터 없이
  3.3V 전용입니다.

`OLED_RES_N` 은 push-pull 출력(5V)이므로 패널의 RES#에 직결하지 말고
분압(예: 1.8k / 3.3k) 또는 레벨 시프터를 쓰거나, 패널의 RES#를 3.3V로
풀업하고 칩 쪽은 사용하지 않는 편이 안전합니다.
(칩은 RES#를 안 쓰더라도 init 시퀀스만으로 동작합니다. 다만 콜드 스타트
신뢰성은 RES# 를 쓰는 쪽이 높습니다.)

## 2. Zybo Z7-20 (3.3V)

핀은 Digilent `Zybo-Z7-Master.xdc` (Rev. B) 에서 그대로 가져왔고,
`fpga/zybo_z7_20/check_xdc.py` 가 Verilog 포트와 핀 배정을 교차검증합니다.

### 전부 Pmod JE 하나에

JE를 고른 이유가 있습니다.

* JE는 **standard Pmod** 라 200옴 직렬 보호 저항이 들어 있습니다. 손으로 배선한
  모듈 앞에 두기에 가장 안전합니다.
* 필요한 신호가 정확히 8개고 JE가 정확히 8개를 줍니다.
* 마스터 XDC 주석에 물리 핀 번호(`Sch=je[1]` ~ `je[10]`)가 그대로 적혀 있어
  모호함이 없습니다.

> **JB/JC/JD 로 옮기지 마세요** (핀을 다시 유도하지 않는 한). 이들은 차동 Pmod라
> 배열 인덱스가 `p[1], n[1], p[2], n[2] ...` 순서입니다. 즉 `jc[1]` 은 JC2가
> 아니라 **JC7** 입니다. 처음에 이걸 착각해서 조이스틱 핀 4개가 틀려 있었습니다.

```
      +--------------------------------------+
   1  |  SCL    SDA    RES#   JS_OK  GND VCC |  6      VCC = 3V3
   7  |  JS_UP  JS_DN  JS_LT  JS_RT  GND VCC |  12
      +--------------------------------------+
```

| Pmod JE | FPGA 핀 | 신호 |
|---|---|---|
| JE1 | V12 | OLED SCL |
| JE2 | W16 | OLED SDA |
| JE3 | J15 | OLED RES# |
| JE4 | H15 | 조이스틱 OK (center) |
| JE5, JE11 | — | GND |
| JE6, JE12 | — | VCC 3V3 |
| JE7 | V13 | 조이스틱 UP |
| JE8 | U17 | 조이스틱 DOWN |
| JE9 | T17 | 조이스틱 LEFT |
| JE10 | Y17 | 조이스틱 RIGHT |

조이스틱 입력에는 FPGA 내부 풀업을 켜 두었으므로 스위치는 GND로 닫히기만 하면
됩니다. I2C 는 모듈에 풀업이 없다면 4.7k 를 3.3V로 추가하세요
(XDC의 `PULLUP TRUE` 는 수십 k라 보조 수단일 뿐입니다).
JE의 200옴 직렬 저항은 400kHz I2C에 문제되지 않습니다.

### 보드 자체

| 보드 | 핀 | 용도 |
|---|---|---|
| SW3 | T16 | 리셋 (올리면 리셋) |
| BTN0 | K18 | 예비 OK/시작 버튼 (조이스틱 없이도 화면 확인 가능) |
| LD0 | M14 | 하트비트 |

### 빌드

```bash
cd fpga/zybo_z7_20
python3 check_xdc.py                      # 포트/핀 교차검증
vivado -mode batch -source build.tcl      # build/snake_zybo.bit
```

125MHz를 5분주해 25MHz를 만들고 코어는 실칩과 같은 RTL을 그대로 씁니다.
`build.tcl` 은 분주 클럭에 대한 `create_generated_clock` 이 실제로 만들어졌는지
확인하고, 안 만들어졌으면 에러로 멈춥니다 (조용히 타이밍이 검증되지 않는 것이
가장 나쁜 경우라서).

## 3. 브링업 순서

1. 전원만 넣고 **LD0**(또는 LED 핀)을 봅니다.
   * 빠른 깜빡임(약 8Hz) = I2C ACK를 못 받는 중
   * 느린 깜빡임(약 1Hz) = 패널 init 성공, 프레임 송출 중
2. 빠른 깜빡임이 계속되면 순서대로 확인:
   * 패널 주소가 0x3D 인 모듈인지 (`oled_ctrl` 의 `I2C_ADDR` 파라미터)
   * SCL/SDA 풀업 유무
   * 패널 VCC, GND
   * `OLED_RES_N` 이 High로 풀려 있는지
3. 화면이 켜지면 타이틀(`SNAKE` / `PUSH OK`)이 나옵니다. OK를 누르면 시작합니다.
4. 프레임레이트가 느껴질 정도로 낮으면 `SCL_HZ` 를 1_000_000 으로 올려 보세요
   (SSD1315는 fast-mode plus를 받습니다). 40fps → 100fps 이상이 됩니다.

## 4. 왜 아두이노가 필요 없는가

DK의 기존 예제(`dino_run`, `pong_vh`, `bricks_out`)는 칩이 픽셀 스트림을
내보내고 아두이노/PICO가 그것을 받아 OLED에 그립니다. 이 설계는 그 MCU가 하던
일 — 패널 초기화, GDDRAM 주소 관리, 바이트 스트리밍 — 을 전부
`oled_ctrl.v` + `i2c_master.v` 로 칩 안에 넣었습니다. 대신 프레임버퍼를 둘 수
없으므로 화면을 실시간으로 계산합니다(`pixel_gen.v`).
